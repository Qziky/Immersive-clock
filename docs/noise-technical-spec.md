# 无基线音频采集与评分技术规范

## 边界

音频采集事实与评分结果完全分离：

```text
AudioWorklet -> 100 ms 特征帧 -> IndexedDB 原始帧仓库
                              -> 内存实时评分
原始帧仓库 -> 后台 Worker 重放 -> 版本化派生评分
```

采集层不得导入评分模型、学习安静基线或生成分数。PCM 只在 AudioWorklet 内用于特征提取，不持久化、不广播、不记录、不导出。

## 帧协议

运行时帧固定包含九个字段：

| 字段               | 含义                      |
| ------------------ | ------------------------- |
| `leaderEpoch`      | 当前单写入者任期          |
| `captureSessionId` | 采集会话 ID               |
| `frameSequence`    | 会话内递增帧序列          |
| `startSample`      | 会话采样轴上的起始位置    |
| `rmsDbfs`          | 原始 RMS                  |
| `aWeightedDbfs`    | A 加权 RMS                |
| `sampleP01Dbfs`    | 100 ms 内绝对振幅 P1 谷值 |
| `zeroRatio`        | 近零样本比例              |
| `clippedRatio`     | 削波样本比例              |

逐帧不保存采样率、帧样本数或时间戳。时间统一由 `startedAt + startSample / sampleRate` 计算；排序、缺帧与连续性只使用样本位置和帧序列。

## 会话协议

会话保存 schema、特征提取器版本、Leader 任期、会话与生产者 ID、开始/结束时间、结束原因、AudioContext 实际采样率、每帧样本数、匿名设备键、声道数、混合方式及实际音频处理状态。

设备变化、Leader 变化、轨道结束或 AudioContext 挂起都结束当前会话。评分窗口不得跨会话拼接。

## IndexedDB v7

数据库包含：

- `noise-capture-sessions`
- `noise-feature-chunks`
- `noise-score-chunks`
- `noise-rescore-state`

原始帧按会话和采样轴的一分钟区间列式存储。序列与样本位置使用基值加 `Uint32Array` 偏移；五个特征列使用 `Float32Array`。

活跃分块每 5 秒通过跨 Store 事务检查点一次。跨分钟或会话结束后标记为 `sealed`，封存分块不再修改。启动新采集前会恢复并封存崩溃遗留会话，最坏丢失约 5 秒尚未检查点的数据。

原始帧与报告统一保留 14 天。IndexedDB 失败时实时评分继续运行，但持久化状态显示失败；不提供 localStorage 原始帧回退。

## 多标签页

Web Locks 优先，localStorage 租约作为回退。任意时刻只有 Leader 创建会话、访问麦克风并写入原始帧。Follower 只接收约 250 ms 合并后的展示快照，不接收原始帧或 TypedArray。

Leader 释放时先停止 Runtime、写入最后检查点并封存会话，再释放领导权。新 Leader 创建新的会话，并在启动时恢复可能遗留的旧会话。

## 评分与重算

实时与历史重算共享 `computeSpectralActivityScore()` 和相同测试向量。首次评分等待 60 秒，之后每 5 秒生成一个滚动窗口。

后台重算按最近会话优先，保存模型版本、配置摘要、完成会话集合和当前检查点。任务可暂停、续跑和幂等重试。配置摘要变化或派生记录缺失时重放原始帧；新模型完成后删除全部非当前模型派生缓存，不再按原始来源状态保留旧评分。应用启动会独立恢复中断会话并调度重算，不依赖麦克风监测客户端启动。

报告遇到高度重叠的异常会话时，以平均覆盖率、质量和开始时间选择单一来源，并写入诊断警告。正常 Leader 交接的边界重叠不受影响。

## 导入导出

常规完整备份的噪音域使用 v4，只包含当前模型派生报告，不包含原始帧。包含 v1-v3 噪音域的旧备份会在预检阶段明确拒绝；不含噪音域的设置与资源备份继续按现有规则恢复。

`.icnoise` v1 是原始特征专用二进制格式，包含会话元数据和列式封存分块，不含 PCM。导入流程先完整解析、检查 schema、引用、冲突和新增存储配额，确认后通过事务写入，并自动启动后台重算。相同数据可幂等导入。

## 产品状态

实时监控显示首次 60 秒采集进度、有效覆盖率和原始帧保存状态。数据设置页显示原始帧实际占用、持久存储状态、重算进度，以及 `.icnoise` 日期范围导出和预检导入。

“保存监测数据”关闭后仍实时评分，但不创建采集会话、不保存原始帧或派生评分。
