# 截图规范

截图的首要任务是准确展示当前产品，而不是用过期界面或不可复现的数据制造更“丰富”的效果。

## 截图来源

- 使用当前提交的生产构建或与发布候选一致的预览版本。
- 不在开发者页面、音频诊断页、测试环境标记或浏览器开发工具打开时拍摄。
- 截图前清除无关通知、鼠标悬停态和调试信息。
- 涉及 PWA 或桌面外壳时，明确画面来自哪个平台；不要用浏览器截图暗示原生客户端。

## 推荐画面组

每个正式版本至少维护以下画面中的 3–5 张：

1. **产品主视觉**：时钟或自习主界面，信息克制，能看出全屏体验。
2. **四种模式**：使用一致背景展示时钟、倒计时、秒表和自习。
3. **自习看板**：课程、目标日期、天气和语录形成清楚层级。
4. **外观设置**：展示当前“视觉外观”结构及预览能力。
5. **环境信息**：环境安静评分或报告，必须带正确口径。
6. **数据管理**：备份、恢复或清理界面，用于使用说明而非首屏广告。

## 尺寸与构图

| 用途          |               推荐尺寸 | 构图要求                                       |
| ------------- | ---------------------: | ---------------------------------------------- |
| README 主视觉 | 1672 × 941 或等比 16:9 | 主时间位于安全区，避免文字贴边                 |
| 社交分享图    |             1200 × 630 | 关键内容放在中央 1000 × 500 区域，适应平台裁切 |
| 桌面功能截图  |             1440 × 900 | 保留完整应用边界，字号在文档中仍可读           |
| 移动端说明    |              390 × 844 | 使用真实响应式布局，不拉伸桌面截图             |
| 方形社区卡片  |            1080 × 1080 | 每张只表达一个主题，避免塞完整设置页           |

高分屏截图可以使用两倍像素采集，但对外文件应控制体积并保留清晰文字。不得非等比拉伸。

## 内容预设

- 使用虚构且中性的课程名称，如“晚间自习”“数学复习”，不要出现真实班级、姓名或考试成绩。
- 目标日期使用仍在未来的示例日期，发布前复核，避免截图长期显示“已结束”。
- 地点优先使用宽泛城市，不展示精确坐标、定位诊断或私人地址。
- 语录优先使用项目内置或明确可传播的自有文本。
- 噪音画面默认展示“环境安静评分”；展示 dB(A) 时必须让“估算”与“已校准”可见。
- 天气、时间和课程数据应彼此合理，不在白天画面配“晚自习已开始”等明显冲突内容。
- 如果使用固定或模拟数据，应在说明文案中标注“演示数据”，不能伪装成实时测量。

## 视觉要求

- 主视觉优先使用默认或接近默认的深色主题，确保用户下载后能认出产品。
- 自定义背景不能降低文字对比度，也不能带未授权人物、影视或品牌素材。
- 保留必要留白，不用箭头、贴纸和大量小字覆盖产品界面。
- 功能讲解图可加编号，但原始截图也应单独保存，便于多渠道复用。
- 不把多个不同时刻、不同版本的界面无标识拼成一张“完整功能”截图。

## 文件处理

- PNG 用于界面和透明图标；照片型背景可在确认无文字损失后使用 WebP/JPEG。
- 去除不必要的 EXIF、设备和位置信息。
- 压缩后检查细线、中文字体和半透明面板是否出现色带或模糊。
- 文件名遵循[素材清单](asset-inventory.md)中的英文 kebab-case 规则。
- 不直接覆盖用途不同的素材；README 主图和社交分享图应分别导出。

## 发布前检查

- [ ] 画面来自当前版本，设置导航名称与代码一致。
- [ ] 没有真实姓名、课程、精确位置、备份内容或设备标识。
- [ ] 没有过期版本号、失效二维码或已结束日期。
- [ ] 没有专业分贝、绝对准确、完全离线等误导表达。
- [ ] 文字在目标展示尺寸下仍可读，颜色对比足够。
- [ ] 图片尺寸、格式、体积和裁切适配目标渠道。
- [ ] 新路径已登记到素材清单，旧引用已处理。
